# 课堂加载第一轮减负（2026-11-05）

本轮把课堂用不到的网络请求移出 Python 文本关卡：独立 teaching.html 不加载 Google/Facebook 等统计脚本，Tracker2 不初始化课堂统计通道；Stripe 使用 pure 入口，实际支付时才加载；Blockly 及代码转积木模块改为打开积木编辑器时加载。地图、角色、配音、Python 执行引擎保持原资源。

## 实测证据与边界

在本机隔离端口 7781、临时学生目录测试 local-python-04；浏览器为 Chrome，冷加载禁用浏览器缓存，第二次导航启用缓存。已有学生数据、正式服务的关卡开放状态未修改。

- 基线实际请求中，移除的 Blockly 相关传输 683,857 字节，Stripe 287,103 字节，统计类 441,433 字节，合计 **1,412,393 字节（约 1.41 MB）**。最终冷/暖两次审计均没有这些请求。
- 最终观测：冷加载 176 个页面请求、11,639,576 字节；暖加载 171 个页面请求、632,447 字节。大部分暖加载静态资源通过缓存复用，请求数不等于完整重新下载次数。
- 为覆盖进入按钮出现后才完成的角色、地面图集，最终采样在按钮出现后再等待 6 秒。最早基线只采到按钮出现，因此**不用两份总量计算整体百分比收益**；按确实被移除的资源单独计量。
- 冷加载按钮出现时间在复测中约 6.3—9.1 秒，暖加载约 2.3—2.7 秒；包含上游网络波动，未证实稳定的启动时延改善。不能把资源减少等同于“40 人问题解决”。
- 使用页面目标的 CDP Network 事件，只统计实际返回的 encodedDataLength；Worker 内部下载和本地服务向上游传输不包含在内。缺少 bytes 的记录表示未在该目标收到完成事件，不代表零资源成本。
- 每次随机载入背景不同，也会改变暖加载流量。未对不同学生共享的服务端缓存做改造。

脱敏清单：`loading-2026-11-05-cold.json`、`loading-2026-11-05-warm.json`、`loading-2026-11-05-removed.json`；不含请求头、Cookie、查询参数或用户/会话 ID。

## 复现与验收

先启动有**独立 TEACHING_STATE_DIR** 的测试服务，勿指向课堂数据目录。工具会自动建立 9999 开头的测试账号，因此禁止默认正式端口 7778，只接受 loopback 地址。准备 Playwright 和 Chromium；可用 PLAYWRIGHT_MODULE 指定已有 Playwright 安装路径，CHROME_EXECUTABLE 指定浏览器路径。

```sh
node teaching/tools/audit-loading.cjs http://127.0.0.1:7781 /tmp/classroom-loading-audit
node --test teaching/test/loading-boundary.test.js
```

审计在支付/统计/Blockly 请求回流或资源请求失败时返回非零状态，并输出脱敏 JSON 和截图。它是单浏览器冷/暖加载检查，不是 40 个真实浏览器的并发压测。

107 项原有课堂测试和 4 项新增加载边界测试通过；Webpack 构建成功，保留上游 573 项警告。新增 JS 通过 ESLint；stripeUtil.js 仅改一行 import，文件原有五处逗号风格问题未混入本次修复，Tracker2 在既有 lint 忽略范围内。实机验证首关编辑、运行、提交，另验证 while/print 关卡。Blockly 加载中切回文本、网络失败可重试有回归覆盖，未对官方付费/积木课程进行端到端验收。

## 部署

本次包含前端和入口路由修改，部署端需要拉取后**重新构建前端并重启原有服务**，保留原 TEACHING_STATE_DIR。可用 Node 22 在仓库根目录执行：

```sh
git pull --ff-only
node --max-old-space-size=8192 node_modules/webpack/bin/webpack.js
```

构建成功后，使用原来的服务管理方式重启；学生刷新页面。只重启、不构建，无法得到新的 teaching.html 和按需加载包。远端网络不通，本轮未代替用户升级远端，也未重启现有本机 7778。
