# 关卡有效定义

这里每个 `<关卡内部编号>.json` 保存该关最终的教学定义，包括地图、机关、场景差异和教师参考代码。它不是生成后的引擎关卡 JSON。

本目录是全部关卡的唯一注册入口，按数字编号排序。文件名必须与正整数 `index` 相同。新增关卡只增加对应 JSON，无须编辑共享注册表；旧基础地图、呈现、物资和验收覆盖链已删除。

## 场景规则

- 关卡定义提供默认值；`scenarios` 中每项提供该场景明确不同的字段。
- 每个注册关卡必须至少有一个可运行场景；省略 `scenarios` 表示一个默认场景，`scenarios: []` 报错，避免目录有条目却没有原生关卡。
- 省略字段表示继承。显式提供字段表示完整替换；数组和嵌套对象不会深合并。
- `[]` 明确清空列表，`null` 明确清空可空配置。每个场景各自拷贝，不共享可变字段。
- 场景 `solution` 替换关卡默认参考解；省略则继承。学生地图和目录不会包含 `solution` 或 `scenarios`。
- 结构迁移保持 `revision`。修改游戏规则是否使旧通过记录失效，需要按进度修订政策另行决定。

`level-catalog` 将有效定义编制为目录、独立场景与教师参考；原生生成器和教师 QA 使用这些结果。`map-designs` 只读取本目录的完整定义，不再推导或覆盖教学内容。

## 生成与检查

- `node teaching/tools/build-levels.js` 生成原生关卡。
- `compileLevels()` 只返回原生关卡对象，不写文件；可以传入一组定义检查修改后的场景。
- `buildLevels(outputDir, { definitions })` 可针对指定定义生成；默认使用完整清单。原生关卡及 `catalog.json` 在 `outputDir`，教师 `references.json` 与可读 `README.md` 在同级 `outputDir-teacher`。教师参考记录源文件链接、编号、章节、修订号、场景、目标和代码，均来自同一次编制。
- `node --test teaching/test/level-compilation.test.js teaching/test/outcome-design.test.js` 检查编制结果与符文室实际机关行为。

## 验证与发布边界

生成先解析并校验全部场景，再生成和序列化全部输出。重复关卡、重复对象/开关/目标、缺失身份、无效游戏坐标、缺失牢门或教学观察对象引用会报告关卡、场景和字段。游戏位置在地图边界内；走廊裁切和装饰火把允许伸出边界。场景编号由数组位置决定，不能覆盖所属关卡编号。默认机制配置仍由对应运行时处理。

完整输出先写同一文件系统的临时目录。学生目录和独立教师目录发布失败时，恢复两个原目录；更新会移除上次遗留的场景文件。恢复本身失败会保留临时备份并在错误中给出路径，供管理员恢复。临时文件系统测试实际制造写入和第二次目录发布失败，核对所有旧文件未变。

这是维护窗口内的整批发布与失败回滚，不是在线零停机或断电事务。停止课堂服务后运行生成，成功后重启服务，让内存中的目录和磁盘场景保持同一代；不要并发运行多个构建。文件系统持续失效或进程被强制终止时，检查 `.levels-build-*` 中的备份，恢复两个完整目录后再启动。不要手改生成 JSON，不要将 `level-definitions/` 或 `levels-teacher/` 配为学生静态资源目录。

[当前自动生成教师参考](../levels-teacher/README.md)是完整清单；历史教师 TXT 保留作讲解笔记，不能作为当前代码的独立来源。`qa-cases.js` 的正例也直接读取最终场景参考代码。运行时选关、教师目录和默认显隐/发布身份读取已经发布的 `levels/catalog.json`，不会把尚未构建成功的源定义暴露给学生。

本轮全部 33 关、54 场景迁移保持原生输出语义与修订号；数量是当前盘点值，不是编制器限制。实际浏览器验收由集成阶段执行，本模块测试不能替代原生运行或课堂试教。
