# 课堂进度保存与恢复

适用范围：当前本地 JSON 存储、一个 Node 服务进程。进度操作在该进程内按学生串行处理；不同学生隔离。不要把同一状态目录挂给多个进程或多台机器。本次验证不构成断电耐久性、跨文件事务或性能延迟保证。

## 保存失败时

保存先写同目录临时文件，再 rename 替换目标。写入或替换失败不删除旧目标；尽力清理本次临时文件。接口返回 HTTP 503 和中文失败说明，不返回“已保存”。现有 JSON 格式不变，错误原因保留为服务端异常 cause，不把文件路径暴露给学生。

原生编辑器自动保存一次只发送一个本地会话请求。失败后恢复待保存字段并显示持久中文提示和“重试保存”按钮；重试读取当前编辑器模型，保留失败期间新增的代码。只在保存成功且没有后续待保存编辑时移除提示。通关弹窗自己的提交仍等待保存确认；失败后不继续导航，提供“重试保存”。提示学生不要刷新或离开页面，可先复制代码到本地文本文件。本地保存已接管底层通用错误提示和旧请求自动重发，因此只显示一份中文恢复提示；其他模型的错误提示保持原行为。网络失败时学生不能假设服务器一定没有保存；重复提交由生命周期保证不重复推进场景。

HTTP 401、403、404、409 不提供无效的反复保存：保留当前编辑器和后续输入，停止向原会话自动重发，说明先复制代码到本地，再通过新标签页课程地图登录、确认开放状态或重新进入关卡并粘贴代码。通关弹窗同样提供新标签页恢复链接和“返回编辑器复制代码”，不把恢复按钮作为再次提交。

教师排查：确认服务进程可写实际状态目录及其 progress 子目录，磁盘可用空间正常；确认没有第二个进程写同一目录。修复后让学生在原页面重试。过期会话或关卡关闭等业务错误仍可能阻止重试，先保留代码，再核对当前场景与开放状态，不绕过权限或覆盖新会话。

## 部署与回退

1. 先在隔离临时状态目录完成定向测试、前端构建和原生浏览器验收。测试脚本仅使用 loopback 随机端口；不得向课堂服务 7778 或 teaching/state 注入故障。
2. 安排停止提交的窗口，提醒所有学生确认保存成功；记录当前提交、启动参数和实际 TEACHING_STATE_DIR，正常停止唯一服务进程。用新目录完整复制该状态目录（账号、登录会话、progress、开放控制等），保留时间标识并限制访问。先检查备份可读，再上线。不能只备份 progress 子目录。
3. 按部署环境构建前端，使用同一状态目录启动一个服务进程。用授权的测试账号确认登录、保存、重新打开、教师进度与场景位置。未确认前不恢复课堂提交。
4. 如需回退，先暂停提交并停止进程，再额外完整备份当前上线后状态。优先回退程序和前端产物，保留最新状态。此票未改变 JSON 格式；其他票的修订字段政策见 progress-revision-policy.md。任何目标旧版本都应先在最新状态的隔离副本上试运行、确认代码和通过记录可读；未知兼容性时不要直接接管课堂目录。
5. 禁止用上线前备份覆盖上线后新增记录。若最新文件确实损坏，保留原件与所有备份，在隔离副本上按学生逐条比对恢复，验证通过后再安排受控替换。无法确认的数据先保留，不执行自动丢弃。

## 可重复的证据

Node 22：`node --test teaching/test/persistence-http.test.js teaching/test/native-save-retry.test.js teaching/test/persistence.test.js`。

- HTTP 故障测试以真实临时目录权限模拟不可写：失败返回 503 和中文重试说明，旧 JSON 字节不变，经 HTTP 读取仍是原代码和完成记录；恢复权限后重试成功。
- HTTP 重启测试正常结束一个真实子进程，再启动新的隔离 HTTP 服务：保留账号、当前场景 1、同一会话 ID、保存代码、场景 0 通过记录和教师的 1/2 统计；旧场景请求仍被拒绝。
- 40 个测试学生同时登录，进行三轮并发保存/重复提交，再逐个读取确认代码、通过记录与完成状态；读取另一个学生的会话返回 404。不据此宣称未经测量的延迟指标。
- 原生客户端测试编译实际 LevelBus CoffeeScript，执行实际 CocoModel 保存包装、Backbone 网络回调与 DOM 按钮：失败不会清空编辑器代码，较新编辑参与重试，成功才解除提示，在途编辑按顺序继续保存。通关弹窗执行实际方法，覆盖断网提示与同代码重试。这是边界传输替身的原生源码测试，不等同于完整浏览器游戏验收。
