# 学习进度修订政策

适用于本地 JSON、单进程课堂服务。结构重构、同内容重新生成、标题/任务说明/贴图更新不作废通过记录。修订号保留用于显示和旧数据迁移；新记录按玩法内容判断，忘记增加修订号也不能沿用旧结果。

## 内容身份与失效范围

`progress-revisions` 对关卡全部公开场景的 `teachingMap` 计算稳定身份：对象键顺序无关，场景顺序和数量有关。只剔除明确列出的呈现与课程目录字段，保留位置、路线、机关、数量、目标、传感器、通关合同、改代码策略，以及嵌套对象的名称和口令。比如库存目标的 `name` 和守卫的 `password` 是学生程序的输入，不能像关卡顶层 `name` 一样忽略。贴图不属于教学玩法定义，原生视觉装饰不参与身份。

玩法内容变化时，本关全部场景需重新验证，以保持“同一份程序通过本关全部场景”的契约；其他关卡的通过历史不被连带删除。需要重试的原因与范围写入 `revisionNotice`，学生地图、继续反馈和教师详情都显示它。完全通过后清除重试提示。账号及当前已保存代码保留，旧通过记录、对应代码、旧完成状态和失效原因归档在 `revisionHistory`，不计入当前完成统计。轮换会话 ID，旧页面无法用旧结果或旧代码覆盖新的尝试。

保存、打开、读取、继续预览、继续、手动切换、学生地图、教师统计及关卡获取均经生命周期模块核对。保存等待 Python 检查时，如果玩法内容发生变化，检查后的提交也被拒绝。前置关卡失效后会重新计算进入权限；教师关闭/隐藏不等于内容失效。

身份依赖编制后的有效教学定义。只改变共享运行时的玩法规则或生成器的玩法语义、却不改变定义时，维护者必须同步增加 `progress-revisions.js` 中 `rules`；结构重构不增加。身份投影算法变更须提供兼容迁移，不能把算法版本变更冒充学生的玩法变化。新增纯呈现字段需加入明确排除列表；未知字段默认属于玩法，避免漏掉实际通关变化。

## 旧 JSON 兼容

旧记录没有 `gameplayIdentity`，无法还原当年全部玩法内容。若 `mapRevision` 等于现有关卡修订，按原有修订契约保留代码、场景通过记录和完成状态（包括仅有 `state.complete` 的更早格式），建立身份并显示迁移说明。不能将缺少元数据本身当作失效原因。

旧记录修订不同或缺失时，无法证明旧结果适用于当前内容；采用保守重试，并明确告知“不具备玩法标识，无法确认原通过结果仍有效”。旧记录进入历史归档，代码和账号照常保留。这是一次兼容性边界，不声称能判断没有记录下来的历史修改是否纯文案。相同修订但部署前未记录的玩法变化也无法自动追溯；上线前应核对内容修订。

新增字段是附加字段，既有账号及会话 JSON 仍可读取。迁移使用现有临时文件加 rename 的保存方式，不变更存储技术。发布前由运维备份实际状态目录；测试只用临时目录。回退前先保存当前目录，保留上线后的代码和新增记录；旧服务不理解内容身份，不能直接把整份旧备份覆盖回来或依赖旧服务进行失效判断。需要回退时先在副本核对历史归档和当前代码，再部署兼容读取版本。
