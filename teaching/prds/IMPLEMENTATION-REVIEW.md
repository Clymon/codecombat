# 三项架构改进：实施与验收记录

日期：2026-11-07。任务：GitHub Issues #1–#16；集成 PR：https://github.com/Clymon/codecombat/pull/17。

## 范围与基线

本次按三份 PRD 实施关卡编制、交互规则、学习进度生命周期。先将课堂工作区保存为 `0ab1a2e`，再逐票建立独立分支、测试和合并。架构审查固定点是该提交；PR 目标仍为 `codex/original-teaching-levels`，因此 PR 差异还包含基线前已获授权的课堂改造。

- 33 个关卡由 `level-definitions/` 统一编制，生成学生目录、原生地图和隔离的教师参考代码；移除七套旧叠加定义。生成失败保留上一代完整产物。
- 地图帮助与真实执行共用交互规则，覆盖守卫、库存、开关、充能、战斗、信号和查询。点击仍只查看帮助，代码指定目标。
- 生命周期模块统一打开、保存、提交、换场景、继续与修订核对；每名学生串行操作，不同学生相互隔离。
- 保存失败保留最新代码并提供恢复入口；关卡玩法变化才要求重新验证，展示文字调整不清空成绩。旧状态迁移保留可信完成记录。

## Standards 审查

发现 1 项问题：身份计算将世界介绍、导师台词和目标展示名称误当成玩法字段，与既定修订政策不符。修复时保留代码可引用的目标名称、守卫口令等语义字段，排除明确的展示字段，并支持旧身份的兼容迁移。

另记录性能风险：一次 33 关进度查询曾重复读取 120 份原生 JSON（约 17.50 MB），普通保存读取 241 份（约 35.09 MB）。这不是已测得的课堂延迟故障；最终实现通过随关卡发布的紧凑进度描述减少重复解析，并检测生成产物变化以失效缓存。

## Spec 审查

发现 2 项问题，其中一项与 Standards 相同：纯展示修改误清成绩；另一项是仅有 `state.complete` 的旧记录首次普通自动保存后丢失完成状态。修复将可信旧完成证据规范化，并覆盖元数据保存、重新打开和进程重启，未为缺少证据的其他场景补发通过。

浏览器还发现保存失败同时出现中文恢复提示和原始英文 JSON 报错。修复仅针对已由课堂保存界面处理的请求，保留其他错误的正常报告。

## 部署边界

当前交付是集成分支和待审查 PR，未合并教学分支、未更新运行中的课堂服务。测试使用临时学生记录和独立 loopback 服务，未改动 `teaching/state` 或 7778 课堂服务。

发布须安排维护窗口：停止服务，备份完整状态目录，生成关卡与构建前端，再启动唯一服务进程。不能在服务读取产物时并发生成。关卡发布具备失败回滚，不承诺断电事务或零停机。学习记录仍为本地 JSON，不是 SQLite；不支持多个进程同时写同一状态目录。回退前保留上线后代码和新增记录，详见 `persistence-recovery.md` 与 `progress-revision-policy.md`。
