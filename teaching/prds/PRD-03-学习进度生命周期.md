# PRD-03：学习进度生命周期

状态：已实施并完成集成验收，待 PR 审阅与部署。优先级：第三批。更新：2026-11-07。

实施结果：[实施与验收记录](IMPLEMENTATION-REVIEW.md)。
## 1. 要解决的问题

当前通过记录、代码 hash、场景切换、会话 ID 轮换、地图修订失效、串行执行和保存分散在不同位置。新增入口时，调用方必须自己记住完整顺序。

继续下一场景与手动切换场景各有一段相似的状态转换；地图修订和提交又各自更新关联字段。已有路由测试，不将本项描述成“当前没有测试”或“已证明会丢记录”。

主要用户：提交与继续关卡的学生、查看进度和控制开放的教师。

## 2. 目标与范围

目标：一次进度操作拥有完整、可验证的生命周期，成功响应与持久化结果一致；旧页面、并发请求和服务重启不会把通过记录记错到另一场景。

覆盖保存代码、记录通过、继续或切换场景、地图修订失效，以及它们与开放权限和前置依赖的衔接。

不包含：迁移 SQLite/Postgres、重做身份认证、远程执行学生代码、多台服务器共享进度、教师重新设计发布界面。

## 3. 必须保持的规则

- 通过记录关联到关卡、场景和用于该次通过的代码；客户端通关信息与保存代码必须一致。
- 多场景关卡遵守现有关卡策略：是否允许场景间修改代码、需要完成哪些场景，不能在重构中自行更改。
- 切换场景后，旧场景迟到的保存不能被记成新场景通过。
- 同一学生的进度变更按一致顺序处理；不同学生互不串号。
- 教师显隐、开放控制与前序关卡要求继续有效；记录完成和允许继续是两个需要分别判断的事实。
- 学生代码、通过记录和教师统计在持久化成功后保持一致。保存失败须显式反馈，不显示已保存。
- 单纯结构重构不使已有进度失效；内容修订是否作废通过记录必须有明确政策。

## 4. 需求

| 编号 | 要求 | 验收条件 |
| --- | --- | --- |
| P1 | 集中完整进度转换 | 路由不再自行拼装场景切换、ID 更新、完成清空与保存的顺序 |
| P2 | 区分场景通过与整关完成 | 部分场景通过不能误算整关完成；教师端与学生端一致 |
| P3 | 保存和通过记录关联准确 | 修改代码后按关卡政策保留或失效相关记录；旧通关代码不得给新代码记通过 |
| P4 | 切换场景隔离旧请求 | 两个标签页、旧页面迟到请求不覆盖或授予新场景进度 |
| P5 | 提交可安全重试 | 相同提交重复到达不重复推进场景、不破坏已保存通过记录 |
| P6 | 保证单进程内并发一致性 | 同一学生的提交和切换不交叉误记；不同学生互不污染 |
| P7 | 修订处理集中 | 仅对政策要求的通过记录失效；保留账号和保存代码，并说明需重试的场景 |
| P8 | 持久化与响应一致 | 保存失败不返回成功；服务重启后恢复成功保存的代码、通过记录和场景位置 |
| P9 | 继续前重新验证可进入条件 | 被关闭的下一关不能通过继续入口绕过；提示等待开放或其他明确原因 |

## 5. 验收场景

1. **保存后重启**：保存未完成代码、完成一个场景，重启隔离服务；代码、通过记录及当前场景正确恢复。
2. **旧页面迟到**：场景 A 完成并进入 B 后，A 的旧保存到达；B 不被覆盖或误判通过。
3. **代码不同**：通关结果关联代码 A，而当前保存为代码 B；不得把 A 的通过归给 B。
4. **不同修改策略**：允许改代码与要求同一代码覆盖多场景的关卡分别执行政策，不互相套用。
5. **重复提交**：同一通关请求重试多次，只产生一致的完成结果；继续入口不因重试跳过场景。
6. **同时提交与切换**：控制请求顺序执行，最终状态对应合法顺序，无混合场景记录。
7. **教师关闭下一关**：当前关通过记录保留；继续入口重新判断，不进入已关闭的关卡。
8. **修订失效**：内容修订按明确政策处理，通过记录变化可解释；账号和代码仍在。
9. **写入失败**：在临时目录模拟写入失败，旧有效文件可读取，界面不显示保存成功，重试可恢复。
10. **班级并发**：使用 40 个隔离测试学生重复保存与提交，验证记录归属和完成一致性；本项不承诺未测量的延迟指标。

## 6. 实施与迁移

1. 收集当前进度状态与各入口转换，写出旧请求、修订、代码变化的行为基线。
2. 先集中场景切换和继续流程，再纳入提交、修订失效及持久化协调。
3. 保留现有文件存储，在临时目录运行完整生命周期测试；不使用课堂学生记录做故障注入。
4. 验证开放控制、前置依赖、学生页面及教师统计的端到端一致性。
5. 如需修改记录格式，先提供旧记录读取测试、备份与可恢复迁移；否则保持现有格式。
6. 交付生命周期规则、兼容性说明、重启/故障/并发验收结果和部署回退步骤。

架构方向：学习进度 module 的 implementation 承担顺序约束；完整行为从 interface 测试。现有临时目录可替代实际存储目录，不需要为假想数据库新增 adapter。

## 7. 风险与回退

当前串行执行只作用于单进程，不能宣称解决多进程或多机器写入。当前持久化为本地 JSON 文件，临时写入后 rename；重启恢复测试不等同于断电耐久性保证。

上线前备份实际状态目录。若写入格式发生变化，必须先验证旧版本是否能读取；回退时禁止用上线前备份直接覆盖上线后新增的学生记录，应先保存新增数据并执行验证过的恢复路径。

## 8. 待确认项

- 地图修改是否一律清空通过记录？建议只有影响通关结果的内容修订才失效；标题、文案、贴图等变化不失效。
- 两个标签页同时编辑同一场景时如何处理？建议检测过期保存并明确提示重新载入，避免静默覆盖；具体行为进入技术设计时与现有编辑器保存流程核对。
- 是否要求多进程部署？建议本期按当前单进程课堂环境验收；多进程写入一致性另立需求。
