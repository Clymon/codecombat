# PRD-01：关卡定义与场景编制

状态：需求草案。优先级：第一批。更新：2026-11-07。

## 1. 要解决的问题

教师和开发者修改一关时，需要在基础地图、呈现修改、物资改造、结果验收改造中追查最终值。场景再通过浅合并生成引擎 JSON，选关目录又读取另一阶段的数据，容易留下旧配置或让展示与运行不一致。

实际例子：第 15 关改为红蓝开关后，还需清除此前呈现逻辑留下的编号标记。该问题已经修复，但暴露出修改者必须理解覆盖顺序的成本。

主要用户：制作关卡的教师、开发者。间接受益者：查看选关说明和进入关卡的学生。

## 2. 目标与范围

目标：一处确定每关、每个场景的最终教学内容，所有使用方从同一编制结果获得所需数据。

范围覆盖当前正式关、教学关、试验关及其场景；关卡目录、生成关卡与教师参考中的共用信息必须对齐。

不包含：新增关卡编辑器、重新设计全部地图、新引擎支持、改变关卡顺序、调整教师发布权限。参考代码允许人工编写，不要求自动求解。

## 3. 用户场景

- 教师把一块石板改成三块：只修改该关的有效定义，地图、目标计数和相关说明同步更新。
- 开发者增加“敌人不存在”的场景：能明确看到该场景与基础场景的差异，不污染其他场景。
- 生成关卡失败：提示是哪一关、哪一个场景、哪个配置存在问题，不能生成一半后留给学生使用。

## 4. 需求

| 编号 | 要求 | 验收条件 |
| --- | --- | --- |
| A1 | 每个关卡身份唯一，场景归属明确，最终值可追查 | 重复身份构建失败；能定位有效源定义 |
| A2 | 每关的最终内容只在一个编制流程中确定 | 目录、游戏和参考材料不各自重做覆盖；后置修改同一对象的链条被消除 |
| A3 | 明确场景如何替换基础配置，尤其是数组、嵌套对象和显式清空 | 能删除继承的标记、机关或敌人；清空不会被当作“继续继承”；场景间无串改 |
| A4 | 目标描述与实际机关使用同一事实 | 三块充能板对应三块板的目标；不存在机关不显示其目标 |
| A5 | 编制先验证再发布全部产物 | 无效坐标、缺失引用、重复对象身份等可检查错误给出关卡与字段定位；失败不混合新旧产物 |
| A6 | 相同源内容生成确定的语义结果 | 连续生成的场景内容、目标与目录一致；不依赖加载顺序的偶然修改 |
| A7 | 学生可下载内容不包含教师参考答案 | 游戏产物排除 solution；教师参考仍能定位对应关卡与场景 |
| A8 | 建立实施时的完整关卡清单 | 实际清单与构建输出一一对应；不把本次审查的数量永久写死 |

## 5. 验收用例

1. **清除旧标记**：第 15 关切换机关设计，显式清除旧标记；所有最终场景中旧标记均不存在。
2. **三个充能板**：第 13 关地图和目标都要求三个充能板；逐个写操作和使用循环的有效解都可通过。
3. **场景独立**：第 19 关各长度场景分别编制，修改一个场景不会改变其余场景的板数和终点。
4. **嵌套替换**：修改某场景库存或敌人配置，未明确保留的旧对象不意外残留；规则有示例说明。
5. **可定位失败**：引用不存在的机关或生成重复身份时，构建报出关卡、场景和字段，已发布文件不变。
6. **消费一致**：对全量清单核对标题、章节、场景数和目标；目录与游戏采用同一编制结果。教师自定义显隐仍生效。
7. **行为回归**：全量参考解运行通过；已有关键失败用例继续失败，且失败原因仍由游戏结果决定。

## 6. 实施与迁移

1. 记录工作区中的最终定义、场景清单与关键行为基线。
2. 先迁移第 13、15、19 关，涵盖机关替换、清空字段和多场景。
3. 比较新旧编制结果；结构整理应保持行为，任何教学行为变化单独记录。
4. 迁移其余关卡，让目录、构建与参考材料使用同一有效数据。
5. 等价性和实际运行检查通过后，移除已失去职责的覆盖逻辑。
6. 交付源定义说明、完整构建检查、场景验收结果与迁移差异清单。

架构方向：关卡编制 module 隐藏组合规则，提高 depth、locality 和 leverage。引擎格式转换属于 implementation；不预设新的 interface 或通用 adapter。

## 7. 风险与回退

主要风险是把“清空”误解释为“继承”，或漏掉原先由呈现逻辑补充的行为。保留迁移前完整源与生成产物作为回退版本；失败时整体恢复同一版本，不混用新旧场景。结构等价迁移不应导致学生通过记录失效。

## 8. 待确认项

- 后续关卡主要由谁编辑？建议本期继续以开发者维护代码为主，教师提出设计需求；可视化编辑另立需求。
- 哪些教师参考材料需要自动更新？建议自动核对关卡名、场景名和参考代码关联，讲解文字仍人工审核。
