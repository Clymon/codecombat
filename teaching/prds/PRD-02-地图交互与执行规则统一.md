# PRD-02：地图交互与执行规则统一

状态：需求草案。优先级：第二批；课堂冲突可优先试点。更新：2026-11-07。

## 1. 要解决的问题

学生点击地图看到“可以对话”，实际代码却可能因隔墙失败。帮助与执行分别解释距离、目标状态等条件，修改规则时可能只改一边。领取和交付也重复维护距离阈值。

已确认的代码差异：守卫帮助的 ready 检查距离，真实执行额外检查墙体遮挡。当前地图是否实际触发尚未验证，不将其写成已复现的课堂故障。

主要用户：通过点击地图探索命令、写代码验证行为的学生。

## 2. 目标与范围

目标：学生看到的交互条件、失败原因和执行结果相互一致，能够据此修改代码。

首批覆盖守卫对话、物资领取和交付；随后覆盖开关、充能石板、信号台、敌人和可破坏门。全局查询说明一并核对。

不包含：用鼠标执行游戏动作、点击替代码选中目标、把所有交互改成相同距离、重做战斗寻路或修改时钟。

## 3. 用户体验要求

- 点击箱子时说明走到哪里领取；站对位置后说明已满足位置条件，领取过则说明不能重复领取。
- 守卫与英雄间有墙时，明确说明隔墙，不能同时显示“当前可以对话”。
- 交付位置满足但数量未知或不足时，说明尚需核对数量，不给出无条件成功承诺。
- 攻击可自动走近；领取和交付仍要求先到位。说明保留各动作的实际差别。
- 回放暂停或拖动时，帮助描述当前显示帧；不能拿未来已开门的状态解释过去关闭的门。
- 每次执行都重新检查当时条件。敌人移动、物品被领取等变化可以使先前提示失效，但必须给出当次原因。

## 4. 需求

| 编号 | 要求 | 验收条件 |
| --- | --- | --- |
| I1 | 位置、遮挡、对象状态等共有判定有唯一规则归属 | 帮助和执行不再各写一份同义判断；修改规则能同时影响两者 |
| I2 | 区分无须接近的查询与需要接近或指定目标的动作 | 帮助准确说明调用范围；鼠标选择不改变代码目标 |
| I3 | 明确“位置满足”与“全部执行条件满足”的差别 | 数量、口令等尚未提供时不宣称动作必定成功 |
| I4 | 给出具体拒绝原因 | 远离、隔墙、已领取、物资不足、目标失效等不混为一个笼统错误 |
| I5 | 提示只读且与当前显示状态一致 | 点击不改变物品、敌人、机关、计时或英雄位置；回放前后状态可逆观察 |
| I6 | 执行使用执行时状态 | 点击帮助后世界变化，再执行能得到新状态下的正确结果 |
| I7 | 保留各动作固有语义 | 攻击自动接近不被改成必须原地；查询不移动人物；wait 默认 1 秒不变 |
| I8 | 保留结果验收与低干扰引导 | 不加入指定语句通关要求，不增加反复弹出的教学遮罩 |

提示文案建议采用“原因 + 下一步”，例如“中间隔着墙，走到守卫正前方再说话”。未知口令不在帮助中自动泄露，仍由关卡环境提供线索。

## 5. 验收用例

| 情景 | 应看到的帮助 | 实际结果 |
| --- | --- | --- |
| 紧邻守卫且无遮挡 | 位置满足；需要正确口令 | 正确口令开门，错误口令保持关闭并反馈 |
| 距离满足但隔墙 | 中间隔墙，不能对话 | 守卫不放行，失败原因与提示一致 |
| 远离补给箱 | 先到箱子前 | 不领取，不改变库存 |
| 箱子已领取 | 已领取，不能重复领取 | 不重复增加物品 |
| 交付位置正确但数量不足 | 位置满足；数量不足或仍需检查参数 | 不误报完成，不产生负库存 |
| 敌人较远且路线可达 | 攻击会自动走近 | 靠近后攻击，不要求学生提前走到攻击距离 |
| 点击敌人后敌人已倒下 | 帮助随显示帧更新 | 执行时按目标失效处理，不操作另一个目标 |
| 查看过去一帧的关闭门岗 | 显示当时关闭状态 | 不泄露后续开门状态，不改变回放 |
| 远处调用全局查询 | 随时可查询 | 返回当前状态，不移动英雄 |

覆盖距离临界点内、临界点和临界点外；具体距离以已确认的游戏规则为准，不在此 PRD 引入新阈值。

## 6. 实施与验证

1. 列出已有交互的条件、参数依赖和可观察结果，确认哪些提示只能判断部分条件。
2. 先用真实执行与帮助对照测试覆盖守卫隔墙、领取和交付。
3. 集中共有规则，保留命中检测、文案呈现和动作执行各自职责。
4. 扩展到其他交互，验证实时运行、暂停、回放和重跑。
5. 删除已经被共同规则替代的重复判定，保留差异化行为测试。
6. 交付交互条件清单、规则一致性测试和浏览器操作验收记录。

架构方向：交互 module 的 interface 隐藏规则组合，而非仅导出一组距离常量。实时状态与回放状态的读取差异是需要确认的 seam；不预先指定 adapter 结构。

## 7. 风险与回退

主要风险是“统一规则”误伤动作差异，或回放读取了实时可变对象。按交互类型小批切换；每批帮助和执行同步回退。不能只回退其中一侧造成新漂移。

## 8. 待确认项

- 多个条件同时失败时先显示哪一个？建议优先显示可行动的原因：目标不存在或已失效 → 位置/遮挡 → 参数或物资条件；危险机关应保留醒目危险提示。
- 是否展示所有未知参数对应的提示？建议只说明必要条件，不显示谜题答案或隐藏剧情。
